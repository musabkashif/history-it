# Architecture

REST requests create a stable job and enumerate an authorized Drive folder exactly once. The ordered manifest is stored in each Batch Queue row. A background orchestrator takes one queued batch at a time, creates a fresh OpenAI request with only governing documents, prior continuation context and that batch's image bytes, validates typed staging output, then writes Asset/Record Staging. The commit service has no Drive dependency: it calls the supplied deterministic planner and applies only its returned rows through header-located Sheets writes. It recalculates metrics, writes summaries/checkpoints and appends 15 validation results. Only a successful readback can close a batch. Restart begins from Batch Queue and staging state; a validated batch is a no-op.

Google Sheets is authoritative. The optional `HistoryIT Jobs` tab is only a job ID to spreadsheet locator; it is not archival state. The `OpenAI Usage` tab is an operational report. Production writes use key-based upsert and conflict detection, never row numbers.
